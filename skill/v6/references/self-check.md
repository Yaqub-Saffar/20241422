# 自我检查机制

> v5 新增。对应 SKILL.md 的**铁律 10「导出前必过机检」**与**阶段 3 自查**。
> 解决的问题：v2~v4 的自查清单靠"人/模型自觉"，清单从 8 条涨到 14 条，
> **规则在膨胀，但执行是软的**——忘了做也没人知道。

## 一、把自查拆成两类

| 类别 | 谁来做 | 在哪 |
| --- | --- | --- |
| **机检**（结构性、可判定） | `tools/check-report.ps1` | 阶段 3 第一道 |
| **人检**（语义性、需判断） | 起草者/用户 | 阶段 3 第二道 |

**原则：能脚本判定的，绝不写进人工清单。** 规则越靠记性，越容易漏。

## 二、机检：`tools/check-report.ps1`

一条命令跑 8 项：

```powershell
powershell -ExecutionPolicy Bypass -File tools\check-report.ps1 -Report output\vN\generated.md
```

| # | 检查 | 判定方式 |
| --- | --- | --- |
| 1 | 五章标题齐全且顺序正确 | 按顺序匹配 8 个标题标记 |
| 2 | 无 `⚠️待核实` 残留 | 搜关键字 |
| 3 | 导图根节点形如 `((密码系统设计第N周))` | 正则 |
| 4 | 导图节点文案 ≤ 12 字 | 逐节点计权（中文每字算 1、连续西文算 1 个词） |
| 5 | 无空话黑名单词 | 关键词表 |
| 6 | 缩写首现带中英对照（近似） | 缩写首现前后 50 字内是否有 `（` |
| 7 | 正文锚点数 == `self-review.md` 行数 | 分别计数比对 |
| 8 | 必备标题存在 | 搜「我的补充/经验总结/出现环境/解决过程」 |

**退出码**：全过 = 0，有 FAIL = 1。脚本对 FAIL 项**定位到具体内容**（超长的节点、命中的词、缺的标题），
不是只报"有问题"。

> ⚠️ **脚本读的是 `.ps1`，PowerShell 5.1 要求脚本文件带 UTF-8 BOM**，否则中文会被当 GBK 解析、
> 直接语法报错。新增或改动脚本后，务必确认文件首三字节是 `EF BB BF`。

## 三、人检（脚本判不了、必须人看）

以下 4 类留给人工，判定要点：

1. **并列项是否各自成句**：每个算法/模式/参数是否被一句话打包（对照 `precision.md` 第一节）。
2. **API 是否写全失败分支**：是否有"调用时机 + 失败返回什么"（对照 `precision.md` 第三节）。
3. **经验总结是否下到根因/能力边界**：不是现象复述（对照 `precision.md` 第六节）。
4. **「我的补充」是否是第一人称真实观点**：不是 AI 总结的复述。

外加阶段 3.5 的锚点确认（对着 `self-review.md` 逐条打勾）。

## 四、阶段 3 的完整顺序

```
① 写草稿
② 跑 check-report.ps1        → 全 PASS 才继续；有 FAIL 先改
③ 人检 4 项 + 阶段 3.5 标锚点 → 产出 self-review.md
④ 再跑一次 check-report.ps1   → 确认锚点与清单一致（第 7 项）
⑤ 进入阶段 4 导出
```

## 五、机检的边界（不要假装它万能）

脚本只做**字面可判定**的事，它**不能**：

- 判断一句话说的是对是错（那是锚点 + 人工的事）；
- 判断并列项有没有被"打包"（语义）；
- 判断经验总结够不够深（语义）。

机检负责"格式和结构一条不漏"，语义正确性仍靠 `precision.md` + 锚点 + 人工。
**别因为有了脚本就放松语义检查。**
