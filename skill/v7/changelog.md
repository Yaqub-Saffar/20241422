# v7 · 变更说明

> 上一版：[`v6/changelog.md`](../v6/changelog.md)
> 反馈依据：[`feedback/v6-to-v7.md`](../../feedback/v6-to-v7.md)（来自 v6 产物的 4 处人工批注）

## 触发变更的问题

v6 的"阈值可配"**生效了**——改 `report.config.yml` 能改变机检判定，v4/v5/v6 旧稿都在新脚本下 9/9 PASS。

**但一测"坏输入"就露馅，而且暴露了两个更早就欠着的稳定性问题：**

| v6 现场 | 根子 |
| --- | --- |
| `max_node_chars: abc` 被解析成 **0**，所有节点"超长" | `[int]::TryParse` 失败时把引用置 0，脚本照用 |
| 拼错的 `max_childern: 2` **静默忽略** | 没有"未知键"概念 |
| 版本号 N 仍靠"取 `output\` 最大版本号 +1" | 目录被手动改动就错，且不报错 |
| 从未在**没见过的输入**上验证过 | v1~v6 用的都是 week03~07，形态相近 |

一句话：**v6 把"内容多怎么办"解决了；但整个 Skill 的稳定性和泛化还没检验过，
而且新引入的配置文件自己就成了一个"静默失效"的新软肋。**

## 根因与对策

### 根因 · 显式性与校验缺失

- 版本号是**推断**出来的，不是**声明**的；
- 配置值是**尽力解析**的（失败就 0 / 无视未知键），不是**校验**过的；
- 泛化从未在**留出输入**上验证。

### 对策 A · 版本号显式声明（`tools/version.ps1`）

按优先级解析并打印来源：命令行 `-Version` → 输入 front-matter 的 `report_version:` → 推断（并提示）。
**能显式就显式，推断必须提示。**

### 对策 B · `check-report.ps1` 增加配置校验

- 非法值（非数字 / 非正数）→ **回退默认 + 打印 `[配置警告]`**，不再静默成 0；
- 未知键 → 打印 `[配置警告]`（提示可能拼写错误）；
- 段标题（`mindmap:` / `summary:`）不算未知键。

### 对策 C · 泛化与稳定性写入规约 + 留出输入实测

新增 `references/stability.md`；铁律 12 明确"版本号与配置必须显式、可校验"。
用从未参与调参的 `input/week08.md`（三份资料 + 多个并列国密算法 + 跨章节引用）做泛化实测，
并重跑 `input/week03.md` 作为 v1↔v7 对比基线。

## 为什么用"显式 + 校验 + 留出输入"而不是改一处常量

- 把版本号从"推断"改成"显式"，是消除**不确定性**——同一 Skill 换目录状态仍产出一致结果；
- 给配置加**校验**，是让坏输入**出声**，而不是静默朝错误方向跑（v5 的机检思想延伸到配置本身）；
- 用**留出输入**实测泛化，是**用证据**代替"看起来应该能跑"。

三件事一个主题：**把"看起来能行"变成"验证过能行"。**

## 验证方法

1. **泛化**：`input/week08.md` 走完整流程，`check-report.ps1 -Week 8` 全 PASS，全程不改脚本；
2. **配置校验**：喂 `max_node_chars: abc` 与拼错键，脚本报警、不误判成 0；
3. **版本号**：`-Version 7` 生效，不给时打印推断值；
4. **回归**：v4/v5/v6 旧稿在 v7 脚本下仍全 PASS；
5. **对比基线**：重跑 `input/week03.md` → `output/v7/week03-rerun.md`，留作终版对比。

**判定：坏配置被拦下、换新输入不改脚本能跑通、版本号可显式指定、旧稿不被误伤，则 v7 有效。**
