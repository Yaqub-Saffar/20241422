# 文风细则

从 `handmade/homework1.md`（第二周手工版）反推出来的写作习惯。**风格以手工版为准，不要改成通用的 AI 报告腔。**

> 本文件管「怎么写句子」。**写什么颗粒度**（抽象名词要落地、并列项不许打包、API 要写失败分支）见 `precision.md`——起草前先读那一份。

## 1. 总结一节

用 `>` 引用块包住整段总结，段内用加粗小标题引导：

```markdown
> **1. C 语言基础（《Head First C》第8章）：** 本章重点介绍了字符串与指针、数组的关系。
> C 语言中字符串本质上是字符数组，以 `\0` 结尾。
>
> **2. 对称加密（《Windows C/C++加密解密实战》第3章）：** 第3章详细讲解了对称加密算法。
```

- 小标题格式：`**N. 主题（《书名》第N章）：**` 或 `**N. 主题：**`
- 主题后紧跟冒号再写内容，**不要**把冒号单独放一段
- 每段 2-4 句，写完"讲了什么"就停，不做价值判断

## 2. 反思一节

严格两级结构：

```markdown
- **AI 总结的不足**：<一句话，最致命的那一点>
- **我的补充**：
  - <要点 1>
  - <要点 2>
```

- 「不足」只写一条，写具体的（"偏向概念罗列，缺少结合加密数据流的实战细节"），
  不写"不够全面""深度不够"这类空话
- 「我的补充」是 2-3 条 bullet，**必须是用户第一人称的判断**，例如
  "在 C 语言中处理加密数据时，字符串的 `\0` 截断问题非常关键"
- 补充里应出现具体的函数名、参数、坑，不要停在概念层

## 3. 实践问题一节

```markdown
#### 问题 1：Windows 环境下 Visual Studio 工具链配置错误，导致无法生成 Makefile

- **出现环境**：Windows 10 + VS Code。
- **解决过程**：
  1. 尝试在 Windows 下编译 OpenSSL 3.5.8，遇到 `'cl' 不是内部或外部命令` 报错。
  2. 在 AI 建议下安装 Visual Studio Build Tools，但配置路径时出现 `vcvars64.bat` 找不到的报错。
- **经验总结**：在 Windows 下进行 C/C++ 密码学开发，环境配置极其繁琐。
```

- 报错原文一律用反引号包裹，保留原始拼写（包括看起来不完整的中文报错）
- 「解决过程」是**编号步骤**，4 步以内；至少 1 步是失败尝试
- 「经验总结」是**结论性的一句话**，不是步骤复述
- 只写用户真实经历过的环境，不许"可能""通常"式推测

## 4. 术语与代码

- 英文技术名词与中文之间加空格：`使用 EVP_EncryptInit_ex 接口`
- 术语首次出现给中英对照：`分组密码工作模式（ECB、CBC、CFB、OFB）`
- 函数名、编译选项、路径、报错 → 反引号
- 教材里的章节号原样保留，不做归一化（用户写 3.4.4 就是 3.4.4）

## 5. 思维导图

```
mindmap
  root((密码系统设计第N周))
    教材
        Head First C 第8章
            字符串与字符数组
            指针与内存地址
        加密解密实战 第3,5章
            对称加密
                AES/DES算法原理
                分组密码工作模式(ECB/CBC/CFB)
    课件
        C语言在密码学中的底层实现
    实践
        数据流与字符串处理
        OpenSSL API 调用
```

- 根节点固定 `((密码系统设计第N周))`，用双括号
- 三大分支固定：`教材` / `课件` / `实践`，顺序不变
- `教材` 分支第二层写「书名 第N章」，第三层才是知识点
- 知识点用 `/` 或 `、` 连接并列项：`AES/DES算法原理`
- 节点文案 ≤ 12 字
- 缩进**只用空格**，mermaid 的 mindmap 对 tab 敏感

## 7. 反面清单

出现以下写法即为不合格：

- 「随着科技的飞速发展」「在当今社会」「综上所述」「相信在未来」
- 「总而言之」「值得注意的是」「不难看出」
- 「首先……其次……最后……」的排比堆砌
- 无信息量的形容词：「非常重要」「极其关键」「广泛应用」
- 把「AI 总结」写成自己的读书感想
