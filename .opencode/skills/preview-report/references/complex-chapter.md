# 复杂章节与边界情况处理

> v6 新增。对应 SKILL.md 的**铁律 11**、**阶段 2「长章节组织」**，
> 以及 `report.config.yml` 的阈值配置。
> 解决的问题：v5 的机检把"格式对不对"管住了，但内容一多、一复杂，
> 会退化成"导图摊平、总结流水账"。这类问题脚本判不了，要靠写法定规矩。

## 一、什么算"复杂章节"

| 情况 | 判据 |
| --- | --- |
| **长章节** | 一本书里本周有 **≥ 3 个重点小节**（如第7章的 7.2 / 7.4 / 7.6） |
| **跨资料** | 一周里横跨 **两本及以上资料**（如 HFC 第9章 + 加密解密实战 第7章） |
| **多概念** | 某一节里并列概念 **≥ 4 个**（如多种模式、多种算法） |
| **深链路** | 知识点有"概念→接口→参数→失败分支"这种多层结构 |

命中任意一条，就按下面的规矩组织，别硬塞。

## 二、长章节：总结按小节号分组

**症状**：重点小节一多，"AI 总结"就变成一堆并列段落，读者对不上"这段在讲 7.2 还是 7.6"。

**做法**：重点小节数 ≥ `summary.group_threshold`（默认 3）时，总结**按小节号分组**，
每组一个加粗小标题，形如：

```markdown
> **7.2 数字签名原理：** ……
> **7.4 EVP_DigestSign 接口：** ……
> **7.6 X.509 证书与证书链：** ……
```

- 每组内部仍然执行铁律 6（并列概念各给机制）；
- 组标题里带上小节号，方便和「学习内容」里的重点小节一一对照。

## 三、跨资料：教材分支按"书名 + 章"再分一层

**症状**：一周两本书，思维导图的「教材」分支下混着两条不相干的线。

**做法**：教材分支下**先按"书名 第N章"建二级节点**，再往下列该书的内容。
不要两本书的要点平铺在同一层。

```
教材
    Head First C 第9章
        ……
    加密解密实战 第7章
        ……
```

## 四、导图超限：先分层，再合并，合并在清单里报备

导图的阈值由 `report.config.yml` 控制：

```yaml
mindmap:
  max_node_chars: 12   # 单节点文案
  max_children: 6      # 每分支直接子节点数
  max_depth: 5         # 层数
```

- 节点文案超限 → 先精简措辞；精简不下来再调大 `max_node_chars`（并在 `self-review.md` 里说明为什么）；
- 分支子节点超限 → 把同类节点**合并到一层**（如把"MD5 128 / SHA-1 160 / SHA-256 256"合成"常见摘要长度"）；
- **任何为了适配阈值而做的合并/放宽，都要在 `self-review.md` 里报备一行**，不许悄悄改。

## 五、深链路：只写到报告需要的深度

「概念→接口→参数→失败分支」这种链，不必全展开。取舍规则：

- **接口**：给出名字 + 调用时机 + 失败语义（阶段 1.5 已要求）；
- **参数**：只写本周用到的那个关键参数，其余不铺开；
- **失败分支**：写"失败了会怎样"，不写每一个错误码。

判据：**读者能不能照它动手复现**，能就够，多了是注水。

## 六、机检怎么配合（脚本判不了语义，只判结构）

- `check-report.ps1` 的第 4 项（节点字数）与第 9 项（分支数/层数）**读配置**；
- 复杂章节调阈值只改 `report.config.yml`，**不改脚本**；
- 语义部分（分组是否清楚、合并是否合理）仍需**人检**——见 `self-check.md`。

## 速查

| 看到 | 就做 |
| --- | --- |
| 一本书 ≥3 个重点小节 | 总结按小节号分组 |
| 一周跨两本书 | 导图教材分支先按"书名 章"分层 |
| 导图某分支挤到 >6 个 | 合并同类到一层，并在清单报备 |
| 某节点文案精简不下去 | 调 `report.config.yml`，清单报备 |
| 知识点层层嵌套 | 只写到"能照做"的深度 |
