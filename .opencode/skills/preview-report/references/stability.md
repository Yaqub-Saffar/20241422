# 泛化与稳定性

> v7 新增。对应 SKILL.md 的**铁律 12**、**阶段 0 版本号解析**，
> 以及 `tools/version.ps1`、`check-report.ps1` 的配置校验。
> 解决的问题：前六版都在同一批（风格相近的）输入上迭代，
> 没证明过"换个没见过的输入还跑得通"，也把版本号押在一个会被手动改动的目录上。

## 一、什么叫"泛化"（对这个 Skill）

**泛化**：换一种**没见过形态**的输入，不改脚本、不改 SKILL，仍能产出合规报告。

本项目用来检验泛化的输入是 `input/week08.md`（hold-out，从未参与 v1~v6 的调参）：

| 与 week03~07 不同的地方 | 为什么容易出问题 |
| --- | --- |
| 一周横跨**三份资料**（HFC 第12章 + 实战第9、10章） | 导图/学习内容组织最容易摊平 |
| 单章内**多个并列算法**（SM2/SM3/SM4） | 铁律 6"并列项各给机制"最容易被违反 |
| 含**跨章节引用**（密钥生命周期 + 国密套件） | 需要按资料分层才不乱 |

## 二、版本号必须显式（不要再推断 `output/`）

**问题**：v1~v6 用"取 `output/` 下最大版本号 +1"确定 N。目录被手动改动
（删了旧版本、建了临时 `output/test`）就会算错，报告标题 / 根节点 / 输出路径全跟着错。

**做法**：`tools/version.ps1` 按固定优先级解析，并打印来源：

```
① 命令行 -Version N                     ← 最优先
② 输入文件 front-matter 的 report_version: N
③ 都没有 → 推断 output\ 最大版本号 +1   ← 会明确提示"这是推断值"
```

用法：

```powershell
powershell -ExecutionPolicy Bypass -File tools\version.ps1 -Input input\weekNN.md
powershell -ExecutionPolicy Bypass -File tools\version.ps1 -Version 7      # 显式指定
```

指定 N 后，报告标题写 `## 第N周预习报告`、根节点写 `((密码系统设计第N周))`
——注意**周次（课程第几周）与版本号（Skill 第几版）是两回事**，别混。

## 三、配置必须可校验（坏输入不许静默）

**问题**（v6 实测暴露）：

| 坏输入 | v6 行为 | 危害 |
| --- | --- | --- |
| `max_node_chars: abc` | 被解析成 **0** | 所有节点"超长"，朝错误方向跑 |
| `max_childern: 2`（拼错） | 静默忽略 | 以为设了、其实没设 |

**做法**（v7 后的 `check-report.ps1`）：

- 非法值（非数字 / 非正数）→ **回退默认并打印 `[配置警告]`**，不再变成 0；
- 未知键 → **打印 `[配置警告]`**（提示可能拼写错误）；
- 段标题（`mindmap:` / `summary:`）不算未知键。

判据：**配置写坏了，先看到警告，而不是先看到一堆莫名其妙的 FAIL。**

## 四、怎么检验泛化与稳定（本版的验收）

1. **泛化**：`input/week08.md` 走完整流程，`check-report.ps1 -Week 8` 全 PASS，**全程不改脚本**；
2. **稳定·配置**：喂 `max_node_chars: abc` 与拼错的键，脚本报警、不误判；
3. **稳定·版本号**：`-Version 7` 显式生效；不给时打印推断值供确认；
4. **回归**：v4/v5/v6 旧稿在 v7 脚本下仍全 PASS（不误伤历史产物）。

## 五、边界（本版不解决）

- 机检仍是**单文件**，跨周术语/术语一致性未纳入；
- 泛化只在**一周**hold-out 上验证，样本有限；
- 版本号"推断兜底"仍在（但已能提示），彻底消除要所有输入都写 front-matter。

这些记在 `feedback/v7-to-final.md` 与 `report/final-analysis.md` 的"局限"里。
