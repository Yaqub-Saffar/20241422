# v5 → v6 反馈

> 来源：`output/v5/human-edited.md` 的 4 处人工批注 + 对 v5 的验证结论。
> 这份文件记录的是**我审阅 v5 产物时发现的问题**，v6 按此修改。

## 一、先验证：v5 的机检真的生效了没有

拿 `output/v5/generated.md` 跑 `tools/check-report.ps1`：

| 测试 | 命令 | 结果 |
| --- | --- | --- |
| 合格稿 | `-Report output\v5\generated.md -Week 6` | **8 / 8 PASS** |
| 回归（v4 旧稿） | `-Report output\v4\generated.md -Week 5` | **8 / 8 PASS**（未被新脚本误伤） |
| 故障稿（故意改坏） | 节点改超长 + 删「经验总结」+ 加「综上所述」 | **4 / 8 FAIL，且逐项定位** |

**结论：v5 的机制生效。** 以前这 8 项靠人逐条勾，现在一条命令给结论，
且失败时报的是「超长的节点是哪个、缺的标题是哪个」，不是笼统的"有问题"。
`human-edited.md` 里 **结构性改动为 0**——说明机检把格式类的坑都挡住了。

## 二、但机检把"格式"管住之后，暴露出真正难的一类：**复杂章节**

v5 这一周（第9章 + 第7章）内容已经偏多：一本书讲库，另一本书讲签名/证书/证书链。
我在审阅时发现，**机检能管的都管住了，管不住的全攒到了"内容多"这件事上**：

| 现象 | 根子 |
| --- | --- |
| 思维导图「教材」分支一路排到 5 个二级节点，再往下就摊平了 | 节点数/层数**硬编码**在脚本和 SKILL 里，章节一大就不够用 |
| 第7章同时有 7.2 / 7.4 / 7.6 三个重点，总结里三条并列，读者要自己对应小节号 | 缺少**长章节按小节号分组**的写法约定 |
| 一周里横跨两本书（库 + 密码），教材分支成了两条互不相干的线 | 没有**跨章节/跨资料**的组织策略 |
| 机检只吃单个文件，无法判断"这周的术语和上周是不是一个写法" | 脚本是**单文件**的，跨周一致性仍靠人 |

一句话：**v5 把"一篇之内格式对不对"解决了；v6 要解决"内容一多、一复杂，怎么不乱"。**

## 三、v6 要改什么（具体、可执行）

| # | 改动 | 位置 | 对应 |
| --- | --- | --- | --- |
| 1 | **新增 `report.config.yml`**：把「导图节点字数上限」「每层节点数上限」从硬编码改成配置项，复杂章节可放宽 | 新文件 + `SKILL.md` 阶段 2 | 第二节 |
| 2 | **`check-report.ps1` 支持 `-Config`**：从配置读阈值，不再写死 12 字 | `tools/check-report.ps1` | 第二节 |
| 3 | **新增阶段 2 的「长章节组织」小节**：重点小节 ≥3 个时，总结**按小节号分组**，每组一个加粗小标题 | `SKILL.md` 阶段 2 | 第二节 |
| 4 | **新增 `references/complex-chapter.md`**：长章节拆分、跨资料（一周两本书）组织、导图超限时的取舍规则 | 新文件 | 第二节 |
| 5 | 导图超限规则：二级节点超过 N 个时，把同类合并到一层，**合并组**在 `self-review.md` 里报备 | `SKILL.md` + `references/structure.md` | 第二节 |

### `report.config.yml` 草案

```yaml
mindmap:
  max_node_chars: 12      # 单节点文案上限（复杂章节可调大）
  max_children: 6         # 每个分支下的子节点上限
  max_depth: 3            # 允许的最大层数
summary:
  group_by_section: true  # 重点小节 >= 3 时按小节号分组
  group_threshold: 3
```

## 四、怎么验证 v6 真的改进了

1. 拿 `input/week07.md`（HFC 第10章 + SSL/TLS 一章）跑 v6；
2. 检查：导图节点是否**在配置上限内**、教材分支是否按小节号/按书分组清楚；
3. **改配置测试**：把 `max_node_chars` 调到 16，重跑 `check-report.ps1 -Config`，
   看它是否**按新阈值放行**（证明阈值真的是配置、不是写死）；
4. 对照 v5：同样内容量下，v5 会摊平、v6 应能分层不超限。

**判定：v6 能在"内容更多的章节"下保持导图不超限、总结按小节分组，
且阈值改动只改配置不改脚本，则 v6 有效。**
