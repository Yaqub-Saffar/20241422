# v1 → v2 反馈

> 来源：`output/v1/human-edited.md` 中的 7 处人工批注。
> 这份文件记录的是**我审阅 v1 产物时发现的问题**，v2 按此修改。
> 原始批注见 `output/v1/human-edited.md` 第 25、40、41、55、66 行。

## 一、7 处批注逐条

| # | 位置 | AI 原话 | 问题 |
| --- | --- | --- | --- |
| 1 | L25 | 五种工作模式「串成密文链」 | 用一句话覆盖五个并列项。只有 CBC 是链式，ECB 逐块独立，CFB/OFB/CTR 都不是链结构。**并列项被概括掉了** |
| 2 | L25 | 「按 PKCS#7 等标准补齐」 | 只给了标准名，没给规则。读者仍不知道要补几个字节 |
| 3 | L25 | 三个 EVP 函数「的分工」 | 只说职责，不说输入输出与调用时机。具体要写缓冲区开多大、哪个函数处理残块 |
| 4 | L40 | 「泄露明文前缀的相等关系」 | 泄露范围表述笼统。IV 复用主要泄露第一块与公共前缀，不是所有块的相等关系 |
| 5 | L41 | 「后果比 CBC 更严重」 | 悬空比较，没点名对比对象，也没说后果具体是什么 |
| 6 | L55 | 「将不会加密剩余数据」 | 漏了失败语义。实际是返回错误，不是静默跳过——两者对调用方是天壤之别 |
| 7 | L66 | 「AI 智能体有明确的权限边界」 | 停在现象。真正的结论是"设备授权需要终端与网页交互，这是能力边界而非配置问题" |

## 二、7 条暴露的是 3 类缺陷，不是 7 个

### A 类：精度下限缺失（6 条：#1-#6）

v1 对"总结"只规定了**格式**（引用块、加粗小标题、2-3 段），
以及一个偏松的**下限**（`SKILL.md:90`：每段至少给出一个具体机制）。

问题在于"至少一个"太松。一段话里讲了五个工作模式、只给一个机制，按 v1 的规则是达标的，
但读者依然不知道另外四个有什么区别——而这正是教材这一节的重点。
#1 和 #5 是同一个病的两种表现：**并列概念被一句话打包**。

### B 类：API 行为只写 happy path（2 条：#3、#6）

`SKILL.md:43` 要求"涉及函数名、参数、默认值、编译选项时必须查到来源"，
但漏了一类：**失败分支与返回值语义**。

`EVP_EncryptFinal_ex` 遇到残块返回错误，和"不做任何处理"，在源码里是两行完全不同的代码，
对调用方来说一个要处理 `int` 返回值、一个可以忽略。v1 允许了后者。

### C 类：结论深度不足（1 条：#7）

`SKILL.md:53` 要求"经验总结是结论性一句话，不许复述步骤"，这半条是对的。
但没规定结论要下到多深，于是 AI 停在最省力的抽象层（"有权限边界"），
而不是最有价值的那层（"什么能力它根本做不到，为什么"）。

## 三、根因：v1 的两个设计问题

### 根因 1 · 阶段顺序错了

v1 的流程是 **阶段 2 起草 → 阶段 3 自查**，把精度当成事后检查项。

但 A 类的 6 条全都能在起草时避免，靠自查补救的问题是：
自查是在成稿上判断"够不够细"，而"够不够细"没有客观标准，只能凭感觉。
换句话说，**v1 把一个需要事前约束的问题交给了事后判断**。

### 根因 2 · 自查清单全是结构性的

`SKILL.md:65-72` 的 8 条自查项，除了第 72 条（空话），
全部在检查**结构**：章节齐不齐、格式对不对、链接有没有、导图三层够不够。

结构合规和内容够细是两件事。v1 的自查清单能保证"五章齐全、格式标准"，
但完全没拦住"用一句话覆盖五个并列项"。

### 新增的 3 条语义精度自查项

写成可判定的形式，否则自查又会退化成凭感觉：

- [ ] 文中每个并列项（多个算法/模式/参数/模式）是否各自有独立说明，没有被一句话打包
- [ ] 文中每个 API 是否都写清了调用时机，且**失败分支**与返回值语义明确
- [ ] 全文是否还有只给名字不给内容的抽象名词（"按标准""采用机制""原理是"）

## 五、怎么验证 v2 真的改进了

不看感觉，看 diff：

1. 拿同一份 `input/week03.md` 跑 v2，得到 `output/v2/generated.md`
2. 与 `output/v1/generated.md` 逐处 diff
3. 只看这 7 个位置：
   - 五个工作模式是否各自有了独立说明
   - PKCS#7 是否给出了补齐规则
   - 三个 EVP 函数是否写清了调用时机与缓冲区大小
   - IV 复用的泄露范围是否具体
   - CTR 与 CBC 的对比是否点了名、说了后果
   - 关闭填充后 `EVP_EncryptFinal_ex` 是否提到返回错误
   - 授权失败的结论是否下到能力边界

**判定标准：这 7 处如果不再需要人工修改，v2 有效。**
如果只改了 3-4 处，说明约束还不够紧，要继续收。
