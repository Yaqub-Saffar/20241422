## 一、v7 这一轮做成了什么

### 1. 版本号不再靠猜

`tools/version.ps1` 按「命令行 `-Version` → 输入 front-matter `report_version:` → 推断 `output\` +1」的优先级解析，
并打印取值来源。**推断时会明确提示**，不再默默算错。

- 实测：不给参数 → 打印 `[version] N=7 来源：推断` 并警告；给 `-Version 7` → 来源显示"命令行"。
- 价值：目录被手动改动（删旧版本、建临时目录）时不会算错版本号，报告标题 / 根节点 / 输出路径不会跟着错。

### 2. 配置文件坏了会出声

v6 引入 `report.config.yml` 后，坏了不说话：

| 坏输入 | v6（错） | v7（对） |
| --- | --- | --- |
| `max_node_chars: abc` | 静默解析成 **0**，全节点"超长" | 回退默认 12 + `[配置警告]` |
| `max_childern: 2`（拼错） | 静默忽略 | `[配置警告]：未知配置键` |

- 实测：喂坏配置，脚本打印 2 条警告但 9/9 仍按默认阈值得出正确结论；
  正常配置**无任何警告**（段标题 `mindmap:` / `summary:` 不算未知键）。
- 价值：**配置写坏了，先看到警告，而不是先看到一堆莫名其妙的 FAIL。**

### 3. 泛化真的被验证了（不是"应该能跑"）

用从未参与 v1~v6 调参的 **`input/week08.md`**（一周跨三份资料 + SM2/SM3/SM4 三个并列算法 + 跨章节引用）
走完整流程，`check-report.ps1 -Week 8` **9/9 PASS，全程没改脚本**。

- `output/v7/generated.md`（week08 泛化产物）
- `output/v7/week03-rerun.md`（同输入重跑 week03，作 v1 ↔ v7 对比基线），同样 9/9 PASS

### 4. 回归无副作用

v4 / v5 / v6 的旧稿在 v7 脚本下仍 **9/9 PASS**，v7 没有误伤历史产物。

### 5. 终稿也能过机检（`-Final`）

此前机检只对 `generated.md` 有效——对真正要交的 `human-edited.md` 跑会误报 FAIL
（终稿锚点已解除，第 7 项却仍拿 `self-review.md` 的 3 行来比）。
新增 `-Final`：检查终稿时第 7 项改为**断言"锚点已全部解除"**。
实测 `human-edited.md -Final` → 9/9 PASS。
